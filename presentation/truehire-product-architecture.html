What Is TrueHire?

One-line definition: TrueHire is a candidate identity verification platform that confirms a real person behind each job application — at the application stage, interview stage, and offer stage — before a hiring decision is made.

The core problem it solves

In remote and high-volume hiring, a recruiter has no way to confirm that the person who submitted a resume is the same person who will show up for an interview — or the same person who will eventually join the company. Candidates can impersonate others, use hired proxies for interviews, or misrepresent their identity entirely. TrueHire fixes this by running a government ID + biometric selfie + liveness check at each of the 3 critical hiring stages, producing a pass/review/fail verdict the recruiter can act on instantly.

02

The 3-Checkpoint System — The Core Concept

Most identity tools verify once and stop. TrueHire runs three separate identity checks — one at each gate of the hiring process — confirming that the same verified person is present at every stage. This eliminates the proxy interview problem and ensures continuity from first contact to hire.

C1

Checkpoint 1 — Application Stage

Before shortlisting

Purpose: Confirm the candidate is a real person with a valid government ID. This is the enrollment step — it creates the biometric identity record for this candidate in the system.

What happens: Candidate scans their government ID (passport, national ID, driving licence), takes a live selfie, and the system runs a liveness check + face-to-document match. AML (Anti-Money Laundering) and PEP (Politically Exposed Persons) sanctions screening also runs here.

System action: On success, the candidate's verified face is enrolled in TrueHire's face pool. All future face comparisons are made against this C1 selfie as the "source of truth".

Government ID Scan Live Selfie Liveness Detection Face-to-ID Match AML Screening PEP Check Face Enrollment
C2

Checkpoint 2 — Interview Stage

Before the interview

Purpose: Confirm that the person attending the interview is the same person who applied. Catches proxy candidates — where someone else shows up to the interview on behalf of the applicant.

What happens: Candidate takes a fresh live selfie (no ID required this time). The system runs a 1:1 face match against their C1 selfie (same person?) and a 1:N face search across all candidates in the pool (is this face someone else's identity?).

Duplicate detection: If the face matches a different candidate in the pool with 70%+ similarity, a duplicate flag is raised — meaning someone is attending interviews as multiple people.

Live Selfie Only 1:1 Face Match vs C1 1:N Duplicate Search Proxy Detection
C3

Checkpoint 3 — Offer Stage

Before offer is sent

Purpose: Final identity gate before the offer is issued. Ensures that after all interviews are done, the same person is still the one receiving the offer — eliminating last-minute identity switches.

What happens: Same as C2 — live selfie, 1:1 face match vs C1, 1:N duplicate search. But now if anything fails, the offer process is blocked and the recruiter is alerted before any commitment is made.

System action: Produces a final downloadable PDF report containing all 3 checkpoint results, scores, and a clear Pass / Review / Fail verdict for the recruiter's file.

03

Recruiter Flow — Step by Step

👤

The recruiter is the user of TrueHire. They log into the dashboard, manage candidates, and decide when to trigger each checkpoint. They never touch the candidate's device — they just send links and read results.

1

Sign Up & Set Up Organisation

Recruiter signs up at app.truehire.com with a work email. Supabase creates their account. Their organisation workspace is ready immediately — no approval waiting period. They can invite team members from the dashboard.

2

Add a Candidate

From the dashboard, they click "Add Candidate" and fill in:

  • Candidate full name
  • Candidate email address
  • Role / job title they applied for

This takes under 30 seconds. The candidate record is created in the database and their status shows "C1 Pending".

3

Send the C1 Verification Link

Recruiter clicks "Send C1 Link". One of three options:

  • Email — system sends the link directly to the candidate's email
  • WhatsApp / Copy — recruiter copies the link and pastes it into any channel (WhatsApp, LinkedIn, Slack, etc.)

The candidate receives a unique, single-use, time-limited URL generated by the Didit API.

4

Wait for C1 Result

The dashboard shows "C1 In Progress" while the candidate completes verification. When done, the status updates to:

  • PASS — verified, face enrolled, safe to proceed
  • MANUAL REVIEW — something needs human review (blurry ID, lighting issue)
  • FAIL — document invalid, liveness failed, AML hit

Recruiter can view detailed scores: liveness confidence, face match %, document validity, AML result.

5

Trigger C2 Before Interview

Once C1 is approved (PASS), the "Send C2 Link" button becomes active. Before scheduling the interview, recruiter sends the C2 link. The candidate completes a quick selfie-only check (~30 seconds). Recruiter sees the face match % against their C1 selfie and a duplicate flag (if triggered).

6

Trigger C3 Before Offer

After interviews are complete and before issuing the offer letter, recruiter sends C3 link. Same selfie check as C2. On completion, the full candidate report is available for download as a PDF — containing all three checkpoint results in a single document.

7

Download Report & Archive

Final PDF report is available from the candidate detail page. It contains: candidate name, role, all 3 checkpoint dates and verdicts, liveness scores, face match percentages, AML status, and a final overall decision. This can be kept on file as evidence of due diligence in the hiring process.

Candidate Flow — Step by Step

🙋

The candidate never logs into TrueHire. They receive a link, open it on any device — phone or desktop — and complete the verification in their browser. No app download required. The whole process takes roughly 2 minutes per checkpoint.

📋

C1 — Candidate Experience

~2 minutes total

1
Opens the link

Taps the link received via email or WhatsApp. Opens in mobile browser — no app needed. Sees a TrueHire branded verification screen.

2
Scans government ID

Uses camera to photograph front (and back if required) of passport, national ID, or driving licence. Document is validated automatically.

3
Takes live selfie

Camera activates. Candidate looks directly into camera. Liveness check runs — detects blinking, head movement to confirm a real person, not a photo.

4
Done — sees result screen

Immediately shown a "Verification complete — your recruiter will be notified" message. No action needed after this.

🤳

C2 & C3 — Candidate Experience

~30 seconds total

1
Opens the new link

Same experience — taps the link, opens in browser. Branded TrueHire screen. No ID required this time, only selfie.

2
Takes live selfie

Camera activates. Quick liveness check — same process as C1. Typically faster because no document scanning step.

3
Done

Confirmation screen shown. In the background, TrueHire compares this selfie to the C1 selfie and scans the face pool for duplicates. The candidate doesn't wait for this — it happens server-side.

Didit — The Verification Engine

Didit is TrueHire's identity verification infrastructure provider. TrueHire does not do its own ID reading, liveness detection, or face matching — Didit's API handles all of that. TrueHire is the product layer: the dashboard, the 3-checkpoint logic, the recruiter UX, and the duplicate detection across candidates.
The 5 Didit API calls TrueHire makes:
API Call When What it does
Create Session When recruiter sends any checkpoint link Generates a unique URL for the candidate to complete their ID/selfie check. Returns a session_url.
Webhook Callback When candidate finishes verification Didit POSTs the result to TrueHire's webhook endpoint with HMAC-SHA256 signature. TrueHire verifies the signature before trusting the data.
Face Search (1:N) — C1 After C1 completes Enrolls the candidate's C1 selfie into the face pool using save_api_request=true. Future searches will find this face.
Face Match (1:1) — C2/C3 After C2 or C3 completes Compares the new selfie against the enrolled C1 selfie. Returns a similarity % and MATCH / NO MATCH verdict.
Face Search (1:N) — C2/C3 After C2 or C3 completes Searches the new selfie across all candidates in the pool. Detects if the face belongs to a different enrolled candidate (duplicate/impersonation detection).

How Verdicts Are Calculated

Verdict C1 (Application) C2/C3 (Interview/Offer)
PASS ID valid + liveness passed + face-to-ID matched + AML clear Face matches C1 selfie + no duplicate found in pool
MANUAL REVIEW Didit returned "manual_review" — typically due to low confidence on a genuine check (blurry photo, poor lighting). Recruiter must inspect manually. Face match % is borderline or duplicate flag raised — recruiter must decide.
FAIL ID tampered or expired / liveness failed (photo/video used) / AML/PEP hit Face does not match C1 (different person) / duplicate candidate (same face found under different name)
⚡

Duplicate detection threshold: If a C2/C3 selfie matches any other enrolled candidate in the pool with ≥70% similarity score — and that match belongs to a different candidate ID — a duplicate_face_flag is set and the other candidate's ID is stored. This catches one person applying as multiple candidates simultaneously.

Security Properties

Webhook integrity

Every callback from Didit is signed with HMAC-SHA256 using a shared secret. TrueHire verifies the signature before processing any result — making it impossible to fake a "PASS" verdict by calling the webhook directly.

Session isolation

Each verification link is a unique, single-use URL with an expiry. It cannot be reused or shared across candidates. It ties back to a specific candidate + checkpoint + organisation.

Row Level Security

Supabase RLS ensures a recruiter from Company A can never accidentally access Company B's candidate data. Enforced at database level, not just application level.

No credential storage

TrueHire does not store government ID images. Only metadata from the Didit decision (scores, document type, name) is stored in the database. Raw biometric data stays within Didit's compliant infrastructure.

Before issuing offer. Same process as C2. Ananya completes in 30 seconds. C3: PASS
